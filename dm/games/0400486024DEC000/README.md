# The Legend of Zelda: Ocarina of Time

The Switch 2 base dump reaches its title screen on the Mac. VideoToolbox decodes the 1920×1080 AV1 track. The movie library runs its NDVE compute shaders to produce the background behind the logo and menu. Gameplay validation is open.

## Profile

SDK 22.2.8, NVN API 231.40, with Nintendo's sead, agl and gsys. The three loaded modules are `main`, `subsdk0` (NintendoSDK_movie), and `sdk`. The NPDM declares 48 MiB of system resources. Startup requests a 6.20 GiB heap, which fits in the profile's 12 GiB reservation with the stack and alias regions. The registered build is the supplied base dump (`v0`).

## Mac dry run

Use the rewritten `patched_v0` and the original extracted `base/romfs`. Build the host with `make -C dm/host GAME=0400486024DEC000` and use the [Mac shader build](../../../docs/development.md#build-by-hand-mac). From the repository, set `DUMP` to the folder containing `base` and `WORK` to the build and run workspace beside it.

```sh
mkdir -p "$WORK/run/save" "$WORK/run/temp" "$WORK/font"
python3 dm/tools/make_ext_font.py "$WORK/font/nintendo_ext.ttf"
DM_ROOT="$WORK" DM_ROMFS="$DUMP/base/romfs" DM_SAVE="$WORK/run/save" \
  DM_TEMP="$WORK/run/temp" DM_MSL_DIR="$WORK/shader/cache" DM_FONT_DIR="$WORK/font" \
  DM_NVN_SHMAP="$PWD/dm/games/0400486024DEC000/shader_map.tsv" \
  DM_WINDOW=1 DM_METAL_HUD=1 DM_FOCUS_KEEP=1 DM_AUDIO=1 \
  dm/host/dmhost "$WORK/patched_v0"
```

`DM_FOCUS_KEEP=1` lets the title keep playing while another app has focus. The profile prewarms the 11 NDVE compute pipelines used by the title. On the Apple M5 that took 17.7 s on a cold run, with a progress screen, and 7 ms with the archive warm. Compiling the same pipelines during the first submission had blocked the first movie frame for tens of seconds. The larger scene shader set also triggers a separate graphics-pipeline prebuild. On the first run with that set, the startup screen took 86.9 s to hand out all pairs, and the remaining workers finished after 110.6 s total.

Start a new game to reproduce the opening scene transition. With the test save and title flow, `DM_KEYS=f2600:A,f2950:A` advances the menu automatically. `DM_NVN_SHDUMP` saves control sections and code for missing keys to the directory it names.

For a run past the opening, copy the committed save folder to the new run's `DM_SAVE` and load slot 00 from the menu. The checkpoint contains both `slot_00/progress.sav` and `slot_00/caption.sav`. The load screen identifies it as **Kokiri Forest Autosave**. A windowed reload reached the playable scene with the HUD and controls, so rendering can be tested without replaying the movie.

## Ultrawide

The game sizes its output from fixed 2560x1440 (docked) constants, so a 21:9 screen showed a 16:9 picture with bars. Building with `DM_ULTRAWIDE=<width>x<height>` (the screen, e.g. `3440x1440`) registers cuts for main e0f3ccfaf50065ae ([patches.py](patches.py)) that give the output size, the render sizes and the output resolution table widths from the screen's ratio at the game's own heights. The 3D view takes its aspect from the render size, so the view widens (Hor+) and nothing is stretched; the HUD and subtitles stay centred, movies stay 16:9 in the middle. Checked on a CB342CK at 3440x1440 (Mac mini M4 Pro, v131072): swap chain 3440x1440, WindowCrop 2752x1152 (2.389:1), title screen, the opening and Link's house fill the screen. Start it with `DM_FULLSCREEN=1`.

## Real speed below 60 fps

The game's frame loop steps a constant per frame, so it played in slow motion below 60 fps. A stub now takes the measured frame time when that is longer ([A fixed step per frame runs slowly below the target](../../../docs/reference/frame-rate.md#a-fixed-step-per-frame-runs-slowly-below-the-target)); `DM_FRAME_DELTA=0` turns it off. Found by gunvalk in [Lichii PR #216](https://github.com/zortos293/Lichii/pull/216).

## Render scale

The launcher's Render scale (`DM_RENDER_SCALE`, 0.5 to 1.0) fixes the 3D views at that fraction of the output and turns the game's dynamic resolution off; 1.0 (the default) keeps the game's own. Docked, the game usually draws 1920x1080 for its 2560x1440 output, so 0.75 is its usual size, lower is faster (0.5: 1280x720, GPU 13.7 ms in Hyrule Castle Town against 16.0-16.2 ms) and higher is sharper (0.9: 2328x1310, 19.0 ms). The game's upscaler network for each ratio is drawn by MetalFX ([A fixed render scale for a game whose dynamic resolution recomputes sizes only on a change](../../../docs/reference/rendering.md#a-fixed-render-scale-for-a-game-whose-dynamic-resolution-recomputes-sizes-only-on-a-change)).

## Open

- Of the task and mesh shaders, nine do not translate: eight foliage shaders stop at Ampere opcode `0x243` (packed conversion, source A `RZ`, mode `0x0000c4ff`; three of them, `604134a5262ff670`, `ecead5cd0569091f` and `fed302d791a4ba43`, are drawn in Kokiri Forest), and one at ISBERD mode `0xb8` in a task or mesh shader. The scene also asks for `d17eefaff4f0bc23`, whose code is in none of the shader archives.
- The title-only build logged 3,331 distinct mapped libraries it could not open, including 363 shaders that failed when setting up programs. A targeted build for those programs and their dependencies translated 6,132 of 6,134 shaders. The two failures are foliage compute shaders `8692b34b521225be` and `83df46a0b1b379b4`, both with Ampere opcode `0x243`.
- With `render_cond` on and the shader build still incomplete, Kokiri Forest showed a hard horizontal cut, sky colour above the horizon over the trees. The volumetric fog composite (`888c1068ac8f7043`, agl) takes a pixel whose R32Float depth copy reads above 0.9999 as sky and paints the sky lookup there. The pass that fills that copy draws with agl's full-screen vertex shader `fb1ed54be1baced1`, which that build had not reached yet, so the host skipped the draw (`draw skipped: no render pipeline`) and dropped the target's store. Retest with the stamped full build. The sky lookup's peaks (about 105, 67 and 36 in RGB) are unverified against the console.
- The opening scene calls `nvnCommandBufferDrawMeshTasksIndirect`, which the host does not implement. On `v0` the probe caught the return at `main+0x2be2dc0`; the branch builds the command buffer pointer in `x0` and the indirect argument address in `x1`. It does not set `x2` on that path. A separate sample of the first 64 bytes at the indirect address returned zeros after the call; the populated record's layout is still unverified. The title-only run logged 11 keys missing from the map. The expanded run captured seven of them before the memory failure. A byte-for-byte comparison found none of those seven code areas in the extracted shader package.
- The 3D scene's CPU cost (37–59 ms a frame, with pool walks of about 33,000 descriptors) is [resolved](../../../docs/reference/frame-rate.md#a-bindless-pool-table-rebuilt-for-every-registration). Open: the GPU's 14–21 ms a frame in Kokiri Forest, which still drops frames below 60 fps; TBDR optimizations are off for this bindless game (`DM_NVN_TBDR=1` turns them on), and attachments load and store about 330 MB a frame.
- The Nov. 4 Lichii branches offer two shader leads. Its [packed conversion lowering](https://github.com/zortos293/Lichii/commit/35c043b3efaa147d1c1afe8a52cdf19fa92b77bf) handles opcode `0x243` with source A set to `RZ` and mode `0x0000c4ff`; both of this game's failed foliage programs use two registers and mode `0x000004ff`, which needs independent verification. Its [floating-point global reduction](https://github.com/zortos293/Lichii/commit/3aa89d1cdbe58a2bd5ded06b9c615c78da2ade70) matches a separate `F32FtzRn` diagnostic in the Mac shader build, where the translator drops that operation. Neither of the two shaders in the sky lookup and draw uses those instructions or the gather opcodes from Lichii's [fog work](https://github.com/zortos293/Lichii/commit/375c4a472bd95fdfaae0de6e3f192499cd14f806).
- Resolved in the log, to be eye-checked at the spots it showed: flat blue holes in the ground with grass and rocks floating over them (Kokiri Forest, the village floor, the Deku Tree) after an hour of play: [textures made for GPU use kept from their CPU rewrites](../../../docs/reference/nvn-objects.md#textures-made-for-gpu-use-kept-from-their-cpu-rewrites). ## Scalar extended multiplication

The rewrite measured below (PR #1741, non-power-of-two literals only) has since been replaced by `mul_extended`, which takes every scalar product out of the optnone helper ([Extended products behind spirv-cross's optnone helper](../../../docs/reference/shaders.md#extended-products-behind-spirv-crosss-optnone-helper), upstream 37f076a52). The measurement is kept as PR #1741's.

The non-power-of-two constant unsigned extended-product rewrite is independent of HMMA changes, tiling, render scale and movie decoding. It preserves the game's original NDVE enhancement. The general mechanism and synthetic tests are described in [Constant unsigned extended multiplication without the optnone mulhi wrapper](../../../docs/reference/shaders.md#extended-products-behind-spirv-crosss-optnone-helper).

The `title-movie` benchmark route starts from an empty save with a neutral stick, keeps original NDVE quality, and measures seconds 20–50 after launch. Use matching host/shader chains, docked mode (`DM_OPMODE=1`), the game's upscaler (`DM_UPSCALER=game`), and `DM_PRESENT_UPSCALE=off`. Set `DM_FOCUS_KEEP=1` for both variants so switching apps does not pause the game (minimizing still does). Compare baseline and candidate as variants of one `scripts/bench.py` invocation. Give each variant its own `host`, `msl`, `shmap` and `pso` paths: the map's adjacent `c1_full.tsv` and `cb_extent.tsv` must match that variant's library stamp. Other games and iOS device execution remain unchecked.

Measured on an M1 Pro (16 GPU cores), macOS 27.2 (26B123), Xcode 27.2 (27B52), game v131072: baseline `51ecd693` / chain `094f939bfef9` versus this isolated rewrite / chain `042a6036306a`. Three alternating baseline/candidate pairs used the same empty save, warmed separate device pipeline archives, `DM_PSO_PREBUILD=0`, `DM_PSO_BUNDLE=off`, the default display link and the Metal HUD. No builds ran during measurement. The desktop was unlocked; startup preparation took 0.83–1.37 s, with all 916 pipeline bases loaded from the archive, before the 20–50 s window. All six runs had no red lines, focus pauses or display-link rescue messages.

The presentation interval p99 remained 76.39 ms, so this is not a frame-pacing fix. Screenshots at 50.5 s cover different movie/animation phases and are not a pixel-equivalence proof. ## Local city pipeline lookup validation

[Repeated archive misses while hybrid pipeline demand is saturated](../../../docs/reference/frame-rate.md#repeated-archive-misses-while-hybrid-pipeline-demand-is-saturated) was found on Apple M5 / macOS 27.0.1, game v131072, SDK 22.2.8. These gameplay measurements used baseline `bd979ced3ae6` and a host carrying local frame-step and packaging changes; the candidate added only the miss cache. They are historical evidence for the mechanism, not a fresh performance comparison on current main. In the city, frame 4500's 300-frame window had frame-time p50/p95/max 107.06/169.34/268.74 ms, GPU p50/p95 24.27/31.89 ms, and CPU translation 113.837 ms per frame. Its 9,208 failed archive searches cost 30,532.8 ms; the demand queue held 384 entries. A live sample spent 287/456 presentation-thread samples under Metal archive lookup.

After the process-local miss cache was installed, the player returned to the same area and reported roughly stable 30 fps. The new frame 3600 window measured frame-time p50/p95/max 28.49/33.78/37.54 ms, GPU p50/p95 27.85/33.33 ms, and CPU translation 6.439 ms per frame. Five failed archive searches cost 14.6 ms over those 300 frames. Earlier new-run windows had similar CPU costs (6.317–6.358 ms). GPU time now dominates those windows.

This is a same-area gameplay comparison, not a deterministic replay: camera, route and cache warmth were not held identical. Only this game was available locally; the regression harness could not locate its manually assembled build layout. The focused archive regression is rerun on the PR base; no new gameplay result is implied.
